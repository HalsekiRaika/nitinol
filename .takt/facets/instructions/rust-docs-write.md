## docs-only 記述手順

1. `plan.md`の「チェックリスト項目 → 記載箇所 → 正本 → 検証」の対応表を全件確認してください。
2. 各項目について、記載前に正本となるテスト・実装・ADR・公開契約を実ファイルで再確認してください。
3. 計画に従ってrustdoc / module doc / README等を記述してください。
4. **プロダクションコードの挙動を変更しないでください。**
   - 許可: doc comment (`///`, `//!`) とタスクで明示された文書ファイルの変更
   - 禁止: シグネチャ、実装ロジック、型定義の意味、テスト、Cargo設定、feature、依存関係の変更
5. 記載内容は正本と一致させてください。
   - 実装が保証していない挙動を契約として書かない
   - 既存テストが示す境界・失敗条件を弱めたり拡張したりしない
6. Rust APIへの参照には、可能な限りintra-doc link（例: ``[`Type`]``、``[`Type::method`]``）を使ってください。
   リンク切れを残さないでください。
7. docs-only範囲では解消できない問題を発見した場合は、コードを直して回避しないでください。
   「判断できない、情報不足、または挙動変更が必要」としてplanへ差し戻してください。
8. 完了前にgit diffを確認し、docs以外の変更を自分が追加していないことを確認してください。
